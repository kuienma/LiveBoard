# 足球训练图转战术板动画 需求文档

Sep 28, 2026 · @kuienma

## 1. 项目概述

做一个适配手机的网页应用：用户拍下足球训练书的一页（训练图 + 文字说明），系统自动生成对应的战术板动画，可播放、微调、导出视频。

**目标用户**：青少年足球教练、家长、训练内容创作者。主要在手机上使用，也要兼顾平板和电脑。

**核心理念**：AI 只负责“看懂”，画面完全由代码渲染。大模型把书页转成一份结构化的训练描述数据（JSON），播放器按数据确定性地画出动画。这样位置、方向准确，每次渲染结果一致，用户也能手动修正。

**不做的事**：不用图片/视频生成模型出画面；不做完整的比赛战术分析软件；第一版不做写实或 3D 风格。

**参考样例**：《运球》章节“从侧边进攻”训练（4 个锥桶，进攻者 A 运球到中间锥桶后 180° 转身避开防守者 B，含基本练法和两个变化）。此页是第一个验收用例，开发时将其照片一并提供。

## 2. 核心流程与功能范围

一次完整使用：上传书页 → AI 生成训练 JSON → 校验 → 播放预览 → 必要时手动修正 → 导出或分享。

&#91;embedded content: 核心流程 · 识别、校验、预览、修正、导出\]

校验不通过时把错误信息发回模型重试；用户可在预览和修正之间反复切换，直到满意。

| 功能 | 版本 | 说明 |
| --- | --- | --- |
| 拍照/上传书页 | MVP | 手机直接调相机，支持从相册选图 |
| AI 识别生成训练 JSON | MVP | 识别场地布局、角色、步骤和所有变化 |
| 战术板播放器 | MVP | 播放/暂停、练法切换、速度调节 |
| 手动修正 | MVP | 拖动锥桶和球员、改文字，不做完整动画编辑 |
| 训练库 | MVP | 保存、列表、删除 |
| 导出 MP4 | MVP | 服务端渲染，横屏 1080p 和竖屏两种 |
| 分享链接 | 后续 | 只读播放页 |
| 卡通小人风格 | 后续 | 面向小朋友，转身时自动慢放高亮 |
| 配音和字幕 | 后续 | 按步骤自动生成讲解 |
| 账号与多人共享 | 后续 | 球队内部共享训练计划 |

## 3. 训练描述数据格式（Drill JSON）

这是 AI 与播放器之间唯一的接口，必须先定义清楚并用 TypeScript 类型 + JSON Schema（建议用 Zod）固化。AI 输出、编辑器修改、播放器渲染、视频导出都只认这一份数据。

**坐标约定**：场地以米为单位，原点在左上角，x 向右、y 向下，与书上图的视角一致（画面左/右 = 数据左/右）。位置可写成坐标 `[x, y]`，也可写成相对对象 `{"at": "mid", "offset": [dx, dy]}`，方便 AI 引用锥桶而不必算坐标。

| 字段 | 含义 |
| --- | --- |
| `meta` | 标题、出处（书名/章节）、训练类别（运球/传球/射门…）、教学要点 |
| `field` | 场地宽高（米）、风格（草地/战术板）、是否画边线 |
| `objects` | 静态器材：锥桶、标志盘、小球门、标志杆，各有 id、颜色、位置 |
| `actors` | 人：球员（进攻/防守/中立）、教练，各有 id、标签、队伍颜色 |
| `balls` | 球：初始归属哪个球员或放在哪里 |
| `variants` | 练法列表（基本练法 + 各个变化），每个有自己的初始站位和动作时间线 |
| `variants[].phases` | 按顺序执行的阶段，同一阶段内的动作同时发生，带时长（秒） |
| `variants[].repeat` | 重复次数；`swap` 表示每轮结束后互换两个对象的引用（用于左右交替） |

**动作类型（第一版）**：`run`（无球跑动）、`dribble`（带球跑，球跟随）、`turn`（原地转身，`degrees` + `awayFrom` 自动判断方向，球从远离对手的一侧绕过）、`pass`（传球，球移到接球人）、`shoot`、`wait`。路径默认直线，可选 `via` 指定途经点生成弧线。箭头和虚线由动作自动生成，不单独存储。

## 4. 模块需求

### 4.1 识别模块（后端）

- 接收图片（JPG/PNG/HEIC），前端上传前压缩到长边约 2000px；支持一次上传多页（一个训练跨页时）。
- 调用支持图片输入的大模型（Claude API），模型名和 API Key 放在环境变量里，不写死在代码中。
- 提示词包含：数据格式说明、坐标约定、动作类型列表、至少 2 个完整示例（few-shot）。明确要求：读文字说明理解训练规则、识别所有“变化”并各生成一个 variant、只输出 JSON。
- 优先使用模型的结构化输出 / 工具调用模式强制符合 Schema。
- 校验（先 Schema，再业务规则）：引用的 id 都存在；坐标在场内；每个 variant 至少一个阶段；`dribble` 的球员此时确实持球。失败则把错误列表发回模型重试，最多 2 次。
- 除 JSON 外，模型还要输出一段“我的理解”（中文纯文字，逐条说明每个练法）和不确定点列表，在前端展示给用户确认。
- 识别耗时可能较长，前端显示进度（上传中 / 识别中 / 校验中）。

### 4.2 战术板播放器（前端核心）

- 输入一份 Drill JSON，输出动画。内部先把数据“编译”成帧时间线（纯函数：给定时间 t，返回每个对象的位置和朝向），再渲染。这个纯函数同时被前端播放和服务端导出复用，确保两边画面一致。
- 画面：草地场地、锥桶（高/矮、颜色）、球员圆点带标签（进攻红、防守白、教练蓝）、足球、当前轮次的跑动虚线。
- `turn` 动作：球绕球员从远离 `awayFrom` 对象的一侧转过去；`slowMotion` 阶段自动减速并高亮转身方向。
- 控件：播放/暂停、重播、练法切换（标签页）、速度 0.5x/1x/1.5x、进度条拖动。
- 画面上方实时显示当前轮次说明，例如“第 2 次：防守者从左边来，运球员向右转身”。
- 自适应：竖屏时场地占满宽度、控件在下方；横屏时场地居中。动画至少 30fps，中档安卓手机不卡。

### 4.3 编辑器（修正 AI 结果）

- 在播放器同一画布上切换到“编辑模式”，显示每个阶段的关键帧。
- 手指拖动锥桶和球员改位置（触控区域至少 44px）；在属性面板中改颜色、标签、阶段时长、练法名称和说明。
- 可增删锥桶和球员，可增删阶段和动作（用下拉选动作类型和目标，不要求用户手写坐标）。
- 撤销/重做；所有修改后数据仍要通过同一套校验。
- 高级入口：直接查看/编辑 JSON。
- 可选：用一句话让 AI 修改（如“把防守者改成从左边来”），后端把当前 JSON + 指令发给模型返回新 JSON。

### 4.4 导出与训练库

- 导出 MP4（主方案，服务端）：后端用无头浏览器（Playwright）打开播放器的“渲染模式”页面，按固定帧率逐帧截图，再用 ffmpeg 合成 H.264 MP4。可选横屏 1920×1080 或竖屏 1080×1920、选择导出哪些练法、是否在画面上叠加中文说明。异步任务，完成后提供下载。
- 导出备选（前端）：Canvas + MediaRecorder 录制，安卓 Chrome 得到 WebM，iOS Safari 得到 MP4；服务端不可用时使用。
- 导出 PNG：每个练法一张带箭头的静态图。
- 训练库：保存训练（JSON + 缩略图 + 创建时间），按类别筛选、搜索标题、删除。默认不保存原始书页照片（见第 7 节）。

### 4.5 数据保存与复用

调整好的训练以 Drill JSON 形式保存，之后直接打开即可播放、继续编辑或导出，不再重新识别。

- **导出/导入 JSON 文件**：单个训练或整个训练库可导出为 `.json` 文件（文件内带 `version` 字段），用于备份或发给其他教练；导入时先经过同一套校验，不通过则提示原因。数据格式升级时提供旧版本到新版本的自动迁移。
- **复制为新训练**：以任一已保存训练为模板生成副本（新 id，标题加“副本”），在副本上修改不影响原训练。
- **版本记录**：每次保存生成一个版本（时间 + 来源：AI 识别 / 手动编辑 / AI 修改 / 导入），可查看历史版本并恢复到任一版本；每个训练至少保留最近 20 个版本。
- 如果第一版不做账号，需在训练库页面提示用户定期导出备份，避免换手机或清除缓存后数据丢失。

## 5. 技术选型与项目结构

全栈使用 TypeScript，monorepo 管理，让数据格式、动画计算在前后端共用同一份代码。

| 部分 | 选型 | 理由 |
| --- | --- | --- |
| 包管理 | pnpm workspaces | 前后端共享 schema 和引擎 |
| 前端 | React 18 + Vite + TypeScript | 生态成熟，易于维护 |
| 样式 | Tailwind CSS | 移动端适配快 |
| 画布 | Konva（react-konva） | 自带拖拽和触控，适合编辑器 |
| PWA | vite-plugin-pwa | 可“添加到主屏幕” |
| 数据校验 | Zod | 一份定义同时生成类型和 JSON Schema |
| 后端 | Node.js + Hono（或 Fastify） | 轻量，与前端同语言 |
| AI | Anthropic SDK（Claude API） | 图片理解 + 结构化输出 |
| 数据库 | SQLite + Drizzle ORM | 起步简单，以后可换 Postgres |
| 文件存储 | 本地目录（可切换 S3 兼容对象存储） | 存缩略图和导出视频 |
| 视频导出 | Playwright + ffmpeg | 逐帧渲染，画面与前端一致 |
| 测试 | Vitest（单元）+ Playwright（端到端） | 引擎必须有单元测试 |
| 部署 | Docker Compose | 后端需要浏览器和 ffmpeg |

建议目录结构：

```
drill-board/
├── apps/
│   ├── web/            # 手机端网页：上传、播放器、编辑器、训练库
│   └── server/         # API：识别、存储、导出任务
├── packages/
│   ├── drill-schema/   # Zod 定义、类型、业务校验规则
│   ├── drill-engine/   # 纯函数：JSON → 时间线，给定 t 返回各对象状态
│   └── drill-render/   # 把某一帧状态画到画布（播放和导出共用）
├── prompts/            # 识别提示词和 few-shot 示例
├── fixtures/           # 测试用书页照片和期望的 JSON
└── docker-compose.yml
```

**主要接口**：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/recognize` | 上传图片，返回 Drill JSON + AI 的理解说明 + 不确定点 |
| POST | `/api/revise` | 当前 JSON + 一句话修改指令，返回新 JSON |
| GET / POST / PUT / DELETE | `/api/drills` | 训练库增删改查（PUT 每次生成新版本） |
| POST | `/api/drills/:id/duplicate` | 复制为新训练 |
| GET | `/api/drills/:id/versions` | 版本列表 |
| POST | `/api/drills/:id/versions/:vid/restore` | 恢复到指定版本（生成一个新版本，不删历史） |
| GET | `/api/drills/export` | 导出单个或全部训练为 JSON 文件 |
| POST | `/api/drills/import` | 导入 JSON 文件，校验后入库 |
| POST | `/api/exports` | 创建视频导出任务，返回任务 id |
| GET | `/api/exports/:id` | 查询进度，完成后返回下载地址 |

## 6. 开发阶段与验收标准

分五个阶段依次完成，每个阶段验收通过再进入下一个。阶段一不接 AI，先把播放效果做对。

### 阶段一：数据格式 + 引擎 + 播放器

实现 `drill-schema`、`drill-engine`、`drill-render` 和播放页，内置第 3 节的示例 JSON。

- [ ] 示例 JSON 通过校验；故意写错的 id 或越界坐标会被拒绝并给出可读的错误
- [ ] 基本练法：B 每次从右边来，A 每次向左转身，球从 A 的左侧绕过
- [ ] 变化一：B 每次从左边来，A 每次向右转身
- [ ] 变化二：B 横穿到对面锥桶，来向左右交替，A 的转身方向随之交替；顶部文字正确显示每轮方向
- [ ] 引擎单元测试：给定时间点断言各对象位置、转身方向、`swap` 后的引用
- [ ] iPhone Safari 和安卓 Chrome 竖屏、横屏正常显示，播放流畅

### 阶段二：AI 识别

实现上传页和 `/api/recognize`。

- [ ] 用“从侧边进攻”书页照片识别，得到三种练法，播放效果与阶段一手写数据一致
- [ ] 准备至少 10 页不同类型的训练图放入 `fixtures/`，写一个批量评测脚本，输出每页是否通过校验及人工对比结果
- [ ] 校验失败会自动重试；两次仍失败时前端给出明确提示，不白屏
- [ ] 前端展示 AI 的理解说明和不确定点

### 阶段三：编辑器 + 训练库

- [ ] 手机上能拖动锥桶和球员、改文字和时长、增删阶段，支持撤销
- [ ] 修改后立即预览；保存后刷新页面数据仍在
- [ ] 训练库列表显示缩略图，可搜索、筛选、删除
- [ ] 导出一个训练的 JSON 文件，在另一台手机导入后播放效果完全一致；导入损坏或格式错误的文件会被拒绝并提示原因
- [ ] “复制为新训练”后修改副本，原训练不变
- [ ] 连续保存几次后可在版本记录中看到各版本，并能恢复到任一旧版本

### 阶段四：视频导出

## 7. 非功能需求与注意事项

- **移动优先**：所有页面先按 375px 宽度设计；按钮和可拖对象触控区域至少 44px；上传按钮直接调起相机。
- **界面语言**：简体中文，文案集中管理，预留多语言。
- **性能**：播放器在中档安卓手机上保持 30fps 以上；首屏加载尽量小于 3 秒。
- **密钥安全**：API Key 只存在后端环境变量，前端永不直连大模型。
- **成本控制**：识别接口按用户/IP 限频；记录每次调用的 token 用量。
- **版权**：训练内容来自出版物。默认不长期保存原始书页照片（识别完即删除），不对外展示书中原文；公开分享功能上线前需要再评估。
- **识别不可能 100% 准确**：书中箭头、虚线含义不统一，文字也常有歧义，所以“AI 理解说明 + 用户确认 + 编辑器”是必须的，不可省略。
